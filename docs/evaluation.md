# DeepResearch Agent 评测报告

这份报告记录了 2026 年 10 至 11 月的检索对照、恢复实验和五道工程决策题。固定文档上的证据选择有改善，本地故障实验验证了已完成动作可以复用。五道实际任务的小样本对照中，Agent 完成 4 道，直接聊天完成 5 道。两组都完成的四题里，Agent 等待时间更长，模型裁判给出的完整要点比例也更低。

## 1. 证据选择

第一轮使用五份公开技术文档，涉及 Python `asyncio`、SQLite 事务、RFC 9111 缓存、`git reset` 和 NumPy 视图与副本。30 道题中 10 道用于开发，20 道用于第一次留出对照。该轮开发题与留出题共享文档，因此评估的是题目级留出。标注由 AI 辅助准备，程序核对引文和字符偏移，尚缺独立人工复核。

每道题给三种选择器相同的问题和候选文档。新版的证据上限采用旧版该题实际使用的证据 JSON UTF-8 字节数。一个标注区间需要由同一来源的选段完整覆盖，相邻或重叠选段可以共同覆盖。按题计算命中标注数除以标注总数，再让每道题等权平均。这个预算衡量证据 JSON 的体积，精确 token 数和整条模型请求长度仍可能不同。

| 20 道留出题 | 原选择器 | 关键词改进版 | BM25 + 本地 E5 + RRF |
| --- | ---: | ---: | ---: |
| 标注证据宏平均召回率 | 47.50% | 70.00% | 77.50% |
| 命中全部标注的题数 | 6/20 | 11/20 | 14/20 |
| 平均证据 JSON 字节数 | 2,376.35 | 2,229.15 | 2,349.70 |

混合组比原版高 30 个百分点，比新版纯关键词多 7.5 个百分点。改动同时涉及排序、要点覆盖和预算内选择。E5 的增量应从第三组与第二组之间读出。

后续针对双语查询，在冻结候选后，从 12 份新官方技术文档构造 60 道留出题和 180 个原文区间。两版每题共享同一候选文档池、查询改写与本地 E5。候选仍受逐题旧版实际字节数约束。

| 新来源留出数据 | 原方案 | 双语选择候选 |
| --- | ---: | ---: |
| 60 题证据覆盖率 | 84.44% | 87.78% |
| 36 道中文提问、英文资料的证据覆盖率 | 80.56% | 85.19% |
| 36 道跨语言题中，全部标注命中比例 | 47.22% | 63.89% |

按来源聚类的配对 Bootstrap 95% 区间包含零。总体差值区间为 −0.56 至 +8.33 个百分点，跨语言差值区间为 −0.93 至 +11.11 个百分点。用这组数字可以描述本批样本的观察结果，推广到其他来源仍需更多验证。

证据预算分配另用了 6 份新文档、30 道题和 90 个区间。两版都命中 80/90 个标注区间，覆盖率为 88.89%。保留原命中区间后，平均证据 JSON 从 3,938.93 降到 3,867.83 字节，减少 1.81%。这些检索实验从已经取得的文档中选段，分母来自标注区间或题目。开放网页搜索召回率和最终回答准确率需要另做实验。

## 2. 结论审查

选择 30 道题，每题准备一份正常草稿和一份注入错误的草稿。旧范围审查、严格摘录审查、编号审查检查同一批草稿，每组最多修复一次输出格式。编号方案让模型返回断言、要点及证据编号，由程序绑定原文。处理异常单独计数，避免用失败充当成功拦截。

| 指标 | 旧范围审查 | 严格摘录审查 | 编号审查 |
| --- | ---: | ---: | ---: |
| 正常草稿通过 | 28/30 | 27/30 | 27/30 |
| 错误草稿明确阻断 | 27/30 | 29/30 | 28/30 |
| 错误草稿漏放 | 2/30 | 0/30 | 1/30 |
| 最终处理异常 | 1/60 | 1/60 | 1/60 |
| 每份草稿平均输出 token，含格式修复 | 144.42 | 471.77 | 154.60 |

相比严格摘录，编号方案平均输出减少 67.23%，审查费用的保守估算减少 39.67%，同时多放行一份条件错误草稿。编号审查在项目中作为显式实验选项。引用绑定验证原文身份和位置，语义支持判断仍来自模型。

## 3. 故障恢复与请求合并

使用本地自编资料和脚本模型启动子进程。子进程在写盘之后调用 `os._exit`，跳过正常清理。原租约自然到期后，由恢复进程以同一任务身份接管。另一子进程在登记模型动作后强制结束，用于观察结果未知时的处理。

| 实验场景 | 对照 | 观察结果 |
| --- | ---: | --- |
| 六份资料已保存四份，恢复阶段抓取次数 | 从头抓取 6 次 | 继续抓取 2 次，减少 66.67% |
| 同一场景，含中断前动作的总抓取次数 | 10 次 | 6 次，减少 40.00% |
| 已保存的规划响应，恢复阶段新增模型派发 | 从头派发 1 次 | 0 次 |
| 同一缓存实例内 16 个相同查询并发到达 | 各自请求共 16 次 | 合并为 1 次上游请求 |
| 模型响应未保存，远端执行结果未知 | — | 阻断恢复，无重发 |

恢复时用动作输入及结果校验和核对检查点，保留原来的尝试次数上限和截止时间。实例内请求合并的数字来自单一键、固定并发量的实验。此处只统计动作数量和状态，远端供应商的执行语义、线上时延和跨进程请求合并另有验证范围。

## 4. 工程决策任务与直接聊天对照

五道题覆盖异步接口部分成功与超时、SQLite 并发事务、个性化 HTTP 缓存、外部 JSON 配置导入和 NumPy 内存取舍。每题预先固定六个评分要点和对应的官方文档位置，共 30 项。问题是新编的应用场景，使用了此前组件实验中保存的文档快照。每题候选池为四份文档。

三个方案使用同一个 DeepSeek Flash API、相同问题和相同简报长度要求，关闭思考模式。直接聊天只进行一次文本回答。Agent 使用本地文档池、默认词法路径、查询改写、审查和有界修订。第三组把 Agent 选出的证据交给同一个模型一次生成回答，因此依赖 Agent 先完成选段。这一组用于观察证据给定后，多步写作流程与单次生成的表现差异。

| 指标 | 直接聊天 | Agent | 给定相同证据后单次回答 |
| --- | ---: | ---: | ---: |
| 五题获得回答数 | 5/5 | 4/5 | 4/5 |
| 共同成功四题的平均生成时间 | 6.00 秒 | 17.08 秒 | 5.53 秒 |
| 模型判为完整正确的要点比例，四题 | 87.50% | 66.67% | 85.42% |
| 模型判为部分正确的比例 | 10.42% | 25.00% | 14.58% |
| 模型判为错误的比例 | 2.08% | 2.08% | 0.00% |
| 模型判为未回答的比例 | 0.00% | 6.25% | 0.00% |
| 模型判定的可执行性，0–4 | 4.00 | 2.00 | 3.88 |

质量评分隐藏组名，每题以正反两种顺序交由同模型裁判，先在题内平均两次评分，再对题目平均。72 个题目、方案与要点组合中，有 12 个组合的两次判定不同。后验排除两项有疑点的评分要求后，三组的完整正确比例分别为 89.58%、70.42%、83.75%，主表保留全部预设要点。该评估使用同模型裁判，样本小且由作者选取。人工核对耗时和独立专家评分尚未测量。

Agent 在共同成功的四题上平均多等待 11.08 秒。计时从开始生成到完整输出，第三组的计时从证据已就绪时开始。人工资料准备、核对与改稿均在这次计时范围之外。

个性化 HTTP 缓存题已检索到 RFC 9111，但词面相关性过滤把它丢弃。该文档命中 18 个主题词中的 12 个，标题命中为零，最终以 `no_evidence` 结束。该失败计入完成率，该题三组未进行联合质量评分。另有报告把格式要求当成研究要点，SQLite 题漏掉了只能同时有一个写事务的明确结论。相同证据单次回答的表现提示，除了检索，报告组织与支持门控也值得单独对照。

## 5. 公开核对范围

[公开结果数据](../examples/evaluation-metrics.json)提供首轮检索逐题结果、实际任务的五道题和评分要求、生成和评分汇总。历史实验保留了题目、分组协议、首次输出、失败记录和评分。发布材料将数值、方法、可核对的公开原文入口和离线演示作为主要证据。历史调用原文、账本与机器运行数据库留在本地。原实验曾使用已保存的 31 个模型步骤回放五个 Agent 任务，复现四份输出和 HTTP 题原失败。公开版的离线演示用于验证发布代码和引用链，历史真实模型对照需要原实验输入和相应模型条件。

首轮检索题依据五份官方技术文档。工程决策题另用了 Python 3.12 JSON 文档。[Python 异步任务](https://docs.python.org/3.12/library/asyncio-task.html)、[SQLite 事务](https://www.sqlite.org/lang_transaction.html)、[RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html)、[Git reset](https://git-scm.com/docs/git-reset)、[NumPy 视图与副本](https://numpy.org/doc/stable/user/basics.copies.html)、[Python JSON](https://docs.python.org/3.12/library/json.html)。
